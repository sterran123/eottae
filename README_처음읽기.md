# 어때? (EOTTAE) — 4인 팀 프로젝트 최종 **착수 패키지** v1.0
작성일: 2026-10-23 / 단계: **계획서·설계서·기본 소스 골격만 준비됨** / 제품 기능 구현·테스트·제출 완료를 의미하지 않음.

## 변경 불가 핵심 정의
**웹사이트/PWA 1개, 브랜딩·회원·설정·안전·공통 디자인 시스템 1개, 사용자 여정으로 연결되는 서비스 3개.**
- **1차 MVP (이번 개발): ① 매칭앱 (`/match`)** — 취향·가치관 프로필, 상대 추천, 공통 질문, 쌍방 관심, 상호 동의 후 1:1 채팅, 신고·차단, 성인 인증.
- **2차 MVP (확장 계획): ② 데이트·소모임 (`/activities`)** — 데이트 코스, 취미/밥/운동 모임, 참가 요청, 일정 투표, 안전 정책.
- **3차 MVP (확장 계획): ③ 모바일 청첩장 (`/invitations`)** — 초대장 에디터, 공개 링크, 행사 시간·장소, 참석 회신(RSVP), 개인정보 설정, 테마 판매.
1차에서 ②③은 **통합 홈의 실제 탐색 가능한 준비중 페이지**까지만 만들고, 실기능은 출시 전이라고 솔직히 표시한다.

## 팀원 / 1차 작업 범위
- 김민기: 전체 기본 틀, 공통 사이트 구조, 홈/내비게이션/테마·로고/PWA shell/문서 통합.
- 오하율: 1차 매칭 프로필·취향·추천 UI/UX 및 접근성.
- 주한태: 인증·성인 확인·매칭 API·DB·RLS 및 보안.
- 손준혁: 1:1 채팅·신고·차단·통합 품질 검증/시연 증빙.
상세 업무·2/3차 재배치는 `1. 프로젝트 계획서/팀_작업지시서_WBS.md`.

## 폴더 구조: 제공된 제4첨부 이미지 준수
```
0. 소스코드/                 Next.js '어때?' 기본 골격 및 실행 가이드
1. 프로젝트 계획서/         기획·브랜딩·팀 작업지시·AI 규칙·사용자 제공 양식 원본
2. 프로젝트 설계서/         요구사항·API 계약·데이터 모델·아키텍처·테스트 케이스
3. 구현 이미지(5장이상)/     실제 구현 후 캡처 목록과 증거 제출 규칙(허위 캡처 금지)
4. 프로젝트 결과 보고서/     진행상태/작성 가이드(구현 전 성과 미기재)
5. 발표자료(PDF)/           **기획 발표용** PDF (완료 발표 자료 아님)
```

## 빠른 시작
1) `0. 소스코드/eottae-web/README.md`를 읽고 `npm install`, `npm run dev`.
2) 루트 및 공통 규칙 `0. 소스코드/eottae-web/AGENTS.md`, `1. 프로젝트 계획서/AI_협업_지시문/RULES.md`.
3) 1차 MVP 상세 요구사항 `2. 프로젝트 설계서/요구사항_마스터.md`, `API_계약_초안.md`, `테스트_케이스_마스터.md`.
4) `1. 프로젝트 계획서/팀_작업지시서_WBS.md`와 `작업표_검증.xlsx`의 이슈 ID로 작업 배정.
5) 업로드된 .xlsx 중 여러 개가 **기존 쇼핑몰/타 프로젝트 예시**이므로 **양식원본만 보관**하고 제출용 별도 작성본을 사용.

## 연령 및 런칭 정책
브랜딩·콘텐츠는 10~40대 누구나 이해할 수 있어도 **1차 실사용자 간 로맨스 매칭·1:1 채팅은 성인(만 19세 이상) 확인된 사용자 전용**. 10대용 기능은 1차 미출시, 무로그인 안내만 가능. 청소년-성인 매칭이 발생하지 않는 서버 수준 차단 필수. 법률 검토가 끝나기 전 민감 데이터 수집·실사용 공개 금지.

## 제출/품질 주의
기획 문서의 '요구사항/완료기준'은 기능 성공을 뜻하지 않는다. '구현 이미지 5장 이상'은 실제 구현과 실사용 테스트 후 채우는 필수 제출 항목. 개발 전 사진을 구현 결과라고 넣지 않는다. 계획의 12주는 예시이며 실제 일정/과정명/담당강사/발표일은 **미확정**.
