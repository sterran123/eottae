## 2. 담당자별 반영 포인트

### 오하율 (MATCH-001/002/009) — 프런트 UI (반영 진행 중)
- **프로필 문답**: 카테고리 탭 + 4지선다 + 답변 삭제. → STEP 3-A 로 구현.
- **관심사 대분류 아코디언**: 이미 반영(장소/음악/음식/여행/스타일).
- **성격 키워드**: MBTI + 관심사로 1차 대체. 키워드 다중선택은 2차 확장 후보.
- 질문은 **운영자가 준비한 고정 세트**로 두는 것을 권장(사용자 자유입력 시 부적절 질문 리스크).

### 주한태 (MATCH-005/006 · 매칭 API·RLS) — 범위 밖, 참고 요망
- **받은 관심 목록 API**: 나에게 관심 보낸 상대 조회. 차단/휴면/미성년/본인 제외(RLS).
- **거리 계산**: 참고자료는 "139.2km"처럼 정밀 표시 →
  **우리는 안전정책상 구간(같은 동네/3km/5km/10km 이내)으로만 내려줄 것.**
  정밀 좌표·실시간 위치 저장 금지(안전_개인정보_연령정책.md).
- **"서로 매력적이라 평가" / 매력도 로직**: 추천 랭킹 근거. 단,
  입증 안 된 수치(일치율 %) 노출 금지(브랜드_가이드.md). 겹치는 관심사 등 사실만.
- **프로필 문답 답변 저장/조회 API**: 문항 id + 선택지 id(또는 자유입력 텍스트) 저장, 답변 삭제(soft delete 권장).
  - DTO 참고(오하율 정의): `QnaAnswer { questionId, optionId|null, customText? }` (src/lib/match/types.ts).
  - 동물상 문항은 보기 id가 동물 코드(dog/cat/fox…). 자유입력은 40자 제한.
- **궁합 집계 API (중요)**: 두 사용자의 문답 답변에서 **같은 보기를 고른 개수**만 반환.
  - 반환은 **겹친 개수(사실)만**: `CompatibilitySummary { sharedCount, bothAnswered }`.
  - **금지**: "궁합 92%"·점수·일치율 등 알고리즘 수치(브랜드_가이드.md).
  - **블라인드 유지**: 추천 단계 집계에서 **상대의 답 내용은 노출하지 않는다**. 개수만.
    상대 답 내용 공개는 쌍방 관심 후(공통 질문 화면)에만.
  - 자유입력(customText)은 궁합 비교에서 제외(텍스트 동치 판정은 1차 미지원).

### 손준혁 (MATCH-007/008 · 채팅·신고·차단) — 범위 밖, 참고 요망
- **좋아요 → 쌍방 매칭 성사 시 채팅 개설** 연계.
- **차단**: 추천/관심 목록에서 상대 차단 시 즉시 상호 비노출.
- 공통 질문(블라인드) 결과를 채팅 입장 트리거로 쓸지 협의 필요.

### 김민기 (CORE) — 공통
- 문답/추천이 쓰는 매칭 전용 색 토큰은 `src/app/match/match-tokens.css`에 격리.
  공통 globals.css 미수정. 브랜드 톤 통합 논의 시 참고.

## 3. 안전·정책 체크 (참고자료와 다르게 가야 할 점)

- 거리: 정밀 km ✗ → **구간 표시만**.
- 접속 시각: 정확한 시각 ✗ → **대략(방금 전/오늘/N일 전)**.
- 사진: 참고 앱은 기본 공개. **우리는 실루엣 기본 + 쌍방 관심 후 공개**(안전정책).
- 수치: "매력도/일치율 %" ✗ → **겹치는 항목 등 사실만**.
- 궁합: "궁합 N점/N%" ✗ → **같은 답 N개(겹친 개수)만**. 추천 단계에선 개수만, 상대 답 내용 비노출.
- 성별/나이: 온보딩 자유입력 ✗ → **성인인증(주한태) 검증값만, 읽기 전용**.
