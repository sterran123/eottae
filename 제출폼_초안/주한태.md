# 최종 제출 폼 작성본 — 주한태

## 이번에 만든 것
「어때?」 3차 최종 제출 — 매칭(1차)·데이트/소모임(2차)·모바일 청첩장(3차) 세 서비스 데모 완성.
내가 맡아 구현·검증한 부분: 가입·로그인 UI(#57)·인증·성인 게이트·매칭 SQL 검증(MATCH-003~006), 소모임 모임 만들기·참가 요청·권한 분기(ACT-002), 청첩장 행사·게스트·공개 정책(INV-002, #103 — 하객 명단 비공개·토큰 만료/재발급·비소유자 거절).
데모 검증 증빙: TC-003·004·007·013·017(비로그인 차단·미성년 거절·추천 제외·참가 보호·비밀키 스캔, #107~#110).
입력은 브라우저 localStorage에만 저장(DEC-11 목업), 이메일 인증만 Supabase 사용.

## 확인하는 방법 · 3단계
1. https://sterran123.github.io/eottae/ 에 접속합니다.
2. 비로그인 상태로 `/match/recommend` 진입이 차단되는지 보고, 「데모로 로그인 → 성인 확인(시연)」에서 만 19세 미만 입력 거절을 확인합니다.
3. `/activities`에서 소모임 참가 요청(중복 방지·요청 취소 전환)과 타인 모임 더보기 메뉴(수정·삭제 미노출)를 확인하고, `/invitations/rsvp/?t=<토큰>`(g 누락)에서 거절 안내를 확인합니다.

## 바뀐 점과 그 이유
① 실연동 계획 → localStorage 목업 고정(DEC-11): 실결제·본인 확인·DB 실데이터는 범위 밖으로 결정, 데모는 「데모 판정」으로만 표기해 과장 없이 검증.
② 청첩장 실사 웨딩 사진 → 자체 일러스트 교체(#118): 출처 확인 불가 사진 제거로 저작권 리스크 제거.
③ 접근성·토큰 정책 보강: RSVP는 `t`+`g` 모두 유효할 때만 폼 개방, 공개 화면에 명단 비공개 유지(#117·INV-002).
④ 증빙 정합: TC 캡처·보고서를 최종 빌드 기준으로 재생성.
