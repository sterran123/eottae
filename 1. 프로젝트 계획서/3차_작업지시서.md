## 1. 목표

`/invitations/`에서 **모바일 청첩장 목업**을 시연한다. 소유자는 예시 청첩장을 만들고 고치고 미리 보며, 하객은 공개 링크로 행사 정보를 보고 참석 회신(RSVP)을 남긴다. 매칭 이용 이력을 강제하지 않는다(`단계_범위고정_인수조건.md`, ADR-004).

3차까지는 **전부 목업(예시 데이터)** 이다(DEC-11, 2026-11-03). 상태는 이 브라우저 `localStorage`만 쓴다. 실데이터·서버 연동은 이 지시서 범위가 아니다.

## 2. 범위

### 한다 (목업)

- 청첩장 목록·만들기·편집·미리보기·테마 적용·반응형 (INV-001)
- 행사·하객·공개 정책 화면: 소유자만 편집, 공개 링크 토큰 재발급, 보존 기간 **안내**, 하객 개인정보 비노출 (INV-002, 화면 데모)
- RSVP 응답 화면·초대 링크 없는 접근 거부 데모·하객별 응답 비공개 (INV-003)
- 기존 테마 미리보기·모의 결제 연결 유지 (INV-004, 이미 있음)
- 화면마다 「데모」 표시. 가상 이름·가상 장소만. 실존 인물·실주소·실전화 금지

### 하지 않는다

- 서버·Supabase 호출, 새 마이그레이션, Edge Function, 외부 API
- 실결제·PayApp 실연동 (DEC-09는 최종 제출 전. 이번은 모의 결제만)
- `package.json`, `FILE_INDEX.csv`, `MANIFEST.sha256`, `supabase/`
- `src/app/globals.css` 직접 수정 (토큰만 재사용)
- 매칭·채팅·데이트·소모임 본문 수정 (`src/app/match/**`, `src/app/activities/**` 등)
- 성인 확인 게이트를 청첩장에 붙이기 (청첩장은 매칭과 독립 진입)

## 3. 완료 기준 (3차 P0를 목업으로 다시 씀)

원문: `단계_범위고정_인수조건.md` 3차 P0 「청첩장 템플릿/행사 정보/공개 링크/RSVP/접근 정책/삭제/공유 메타태그」, 출시 Gate 「공개 RSVP 링크가 게스트 개인 정보를 노출하지 않음 + 스팸/봇 제한 + 저작권/행사정보 삭제 정책」. 요구사항 최소 인수: INV-001~003. TC-015·TC-016.

이번 단계에서는 **이 브라우저 화면**으로 아래를 보이면 P0 목업을 끝낸 것으로 본다. 서버 403·실속도 제한·클라우드 삭제는 완료로 쓰지 않는다.

| P0 원문 | 목업 끝난 기준 | 확인 |
|---|---|---|
| 청첩장 템플릿·행사 정보 | 예시 청첩장 2~3개가 목록에 있고, 소유자 화면에서 제목·날짜·가상 장소·인사말을 고치고 저장(이 브라우저)할 수 있다 | 360px·데스크톱, 6테마 |
| 테마·미리보기·반응형 (INV-001) | 미리보기에 고른 테마가 반영된다. `DEMO_THEMES` 4종과 연결한다. 터치 44px, 가로 넘침 없음 | 360px에서 잘림 없음 |
| 공개 링크 | 불규칙 토큰이 붙은 링크로 하객 화면이 열린다. 검색엔진 미노출은 해당 페이지 `robots: noindex` + 화면 안내 | 토큰 없는 주소·폐기된 토큰은 행사 정보가 안 보인다 |
| RSVP | 초대(게스트) 토큰이 있는 링크에서만 회신 폼이 열린다. 참석 여부·인원·식사(입구 안내 문구)를 이 브라우저에 남긴다 | 토큰 없으면 「초대 링크가 없어 회신할 수 없어요」 |
| 접근 정책 (INV-002, TC-015) | 소유자가 아닌 데모 판정에서는 편집·하객 목록이 안 열린다. 안내 문구 | 쿼리로 편집 주소를 넣어도 거절 |
| 하객 개인정보 비노출 (INV-003, TC-016, ADR-004) | 공개 하객 화면에 게스트 명단·다른 사람 RSVP·전화·실주소가 없다 | 소유자 화면에서만 하객·회신 목록 |
| 링크 토큰 재발급 | 소유자가 재발급하면 새 토큰만 열리고 옛 토큰은 만료 화면 | 같은 브라우저에서 옛 링크 재방문 |
| 삭제 | 소유자가 이 브라우저에서 해당 청첩장을 지울 수 있다. 행사 후 삭제·보존은 **안내 문구**. 기간 숫자는 DEC-06 미결이라 지어내지 않는다 | 지운 뒤 목록·공개 링크 둘 다 없음 |
| 공유 메타태그 | 하객 화면에 제목·날짜·가상 장소 미리보기 카드. 페이지 공통 metadata 제목은 「모바일 청첩장」. **토큰별 동적 OG는 Pages 정적 export에서 불가** — 실데이터 단계에서 재검토 | 화면 카드 + `noindex` |
| 스팸/봇 제한 | 같은 게스트 토큰으로 이 브라우저에서 연속 제출하면 「잠시 뒤에 다시 시도해 주세요」. 서버 속도 제한이 아니다 | 연속 제출 |
| 데모 표시 | 2차와 같이 상단 뱃지. 예: 「데모 데이터로 동작하는 3차 미리보기」 (`ActivitiesDemo`의 `act-preview-badge`) | 모든 청첩장 화면 |

3차 P1(커플 연대기·테마 꾸미기·축하 메시지)과 방명록은 **이번 P0 목업 완료 조건이 아니다**. 화면에 넣으면 「제안·P1」이라고 적는다.

## 4. 화면 목록과 경로

정적 export + `trailingSlash: true`라 **동적 `[token]` 세그먼트는 `generateStaticParams` 없이 빌드되지 않는다**. 2차는 상세를 쿼리로 연다(`src/lib/activities/href.ts`, `/activities/?gathering=`). 3차 공개 링크도 같은 방식을 쓴다.

논리 계약(`API_계약_초안.md`) `GET /invitations/:token`, `POST /invitations/:token/rsvp`는 **화면 동작의 이름**이다. 이번 단계는 HTTP API를 만들지 않는다.

| 화면 | 경로 | 근거 | 담당 |
|---|---|---|---|
| 허브·내 청첩장 목록 | `/invitations/` | 이미 있음. 홈 IA, CORE-001. 준비중 본문을 목업 목록으로 교체 | 오하율 |
| 테마 미리보기·모의 결제 | `/invitations/` 하단 유지 | 이미 있음 — `ThemePreviewSection`. INV-004 | 김민기 연결 확인 |
| 만들기 | `/invitations/new/` | **제안** (2차 `/activities/new/` 패턴) | 오하율 |
| 편집 | `/invitations/?edit=<id>` | **제안** (정적 export 쿼리) | 오하율 |
| 미리보기 | `/invitations/?preview=<id>` | INV-001. 경로 형식은 **제안** | 오하율 |
| 공개 하객 | `/invitations/p/?t=<sharingToken>` | API `GET /invitations/:token`, ADR-004. 경로 `/p/`·쿼리 `t`는 **제안** | 오하율(뼈대) + 주한태(명단 없음) |
| RSVP | `/invitations/p/?t=<sharingToken>&g=<guestToken>` | INV-003, API `POST .../rsvp`. 쿼리 `g`는 **제안** | 손준혁 |
| 소유자 정책(토큰 재발급·보존 안내·하객 목록) | 편집 화면 안 패널 | INV-002, 입구 페이지 기능 04 문구 | 주한태 |
| 방명록·축하 메시지 | (경로 없음) | **제안·P1** (`단계_범위고정_인수조건.md` 3차 P1 「축하 메시지」). 이번 P0 아님 | — |

하객 공개 화면은 매칭 성인 게이트(`DemoEntryGuard`)를 쓰지 않는다.

## 5. 공통 데모 데이터 약속

2차 `src/lib/activities/`를 본떠 **`src/lib/invitations/`** 에 둔다.

### 누가 먼저

1. **오하율이 첫 PR**로 `types.ts` · `demo-data.ts` · `demo-storage.ts`를 연다. 화면은 이 PR에 없어도 된다. `href.ts`도 이 PR에 두는 것을 권한다.
2. 주한태·손준혁은 그 PR이 **머지된 뒤** 같은 타입·키만 import 한다. 각자 `types.ts`를 새로 만들지 않는다.
3. 필드가 더 필요하면 이슈에 적고 오하율 PR로 타입을 고친 다음 화면 PR을 연다.

### `types.ts` — 화면용 필드 (DB 논리모델을 camelCase로)

`DB_논리모델_전체3단계.md`의 `INVITATION` · `RSVP` · `INVITATION_MEDIA`. 네트워크 호출 없음.

**Invitation**

- `id`, `ownerId` (데모 문자열)
- `title`, `hostNames`(가상 두 이름), `weddingDate`, `venueLabel`(가상 장소만), `greeting`
- `sharingToken`, `visibility`, `expiry`, `themeId`, `status` (`draft` · `published` · `expired` · `revoked`)
- `viewerIsOwner` — 이 브라우저를 소유자로 볼지 (2차 `viewerIsHost`·`mine`과 같음)
- 선택: `startsAtLabel`, 식사 안내 문구(입구 페이지 「식사·인원」)

**Guest**

- `id`, `invitationId`, `displayName`(가상 닉네임), `guestToken`
- 전화·이메일·실주소 필드 **없음**

**Rsvp**

- `invitationId`, `guestToken`, `response` (`yes` · `no` · `maybe`), `partySize`, `note`, `respondedAt`
- 선택: `meal` (입구 안내의 식사)

**InvitationMedia (선택)**

- `invitationId`, `order`, 이 브라우저 data URL 또는 사이트 경로. 실존 인물 사진 금지. 서버 업로드 없음 (2차 소모임 커버와 같음)

### `demo-data.ts` — 예시 청첩장 2~3개

실존 인물·실주소·실전화·실상호 금지. 2차처럼 가상 지역(노을구·달동네 등)만.

지시 예시(구현 시 이 취지로 가상 이름을 새로 지어도 된다):

1. 소유자 예시 — 이서윤 · 박하람, 가상 장소 「노을구 달빛홀」, `viewerIsOwner: true`, `themeId`는 `DEMO_THEMES` 중 하나(`spring-card` 등), 하객 닉네임 몇 명(솜사탕·종이배처럼 가상만)
2. 하객 열람 예시 — 김구름 · 최별, 「달동네 종이별 정원」, 공유 토큰으로만 공개 화면
3. (권장) 만료·폐기 예시 — 옛 토큰이 열리지 않는 화면용

RSVP 시드: 일부 하객만 회신. 공개 화면 데이터에는 넣지 말고 소유자 목록용으로만 둔다.

### `demo-storage.ts`

- 키 이름: **`eottae.invitations.demo.v1`**
- 이 브라우저에서 만든 청첩장, 토큰 재발급 결과, RSVP, 삭제만 저장. 서버로 보내지 않음
- 테마 모의 결제 키 `eottae_demo_theme_purchases_v1`과 **섞지 않음**
- 첫 PR에서 `src/lib/demo/clear-demo-device.ts`의 `DEMO_DEVICE_STORAGE_KEYS`에 `eottae.invitations.demo.v1`를 넣는다 (설정 「이 브라우저에서 지우기」에 포함)
- 2차처럼 길이 한도·파싱 실패 시 빈 상태

## 6. 사람별 작업

의존: **1단계 오하율 타입·데이터 PR 머지 → 2단계 화면 PR → 3단계 QA·캡처**.

### 오하율 (메인, INV-001)

전체 화면 흐름(목록→만들기→편집→미리보기→공개 링크)을 정하고, 타입 첫 PR을 연다.

- [ ] **1단계 첫 PR** `src/lib/invitations/types.ts`, `demo-data.ts`, `demo-storage.ts` (권장 `href.ts`). 키 `eottae.invitations.demo.v1`. `clear-demo-device.ts`에 키 추가
- [ ] `/invitations/` 준비중 본문을 목록·데모 뱃지로 바꾸고, **`ThemePreviewSection`은 하단 유지**
- [ ] 만들기 `/invitations/new/` (**제안 경로**): 제목·두 이름·날짜·가상 장소·인사말·테마
- [ ] 편집 `/invitations/?edit=` (**제안**): `viewerIsOwner`만
- [ ] 미리보기: 테마 토큰(`--paper`·`--ink`·`--brand` 등)만. hex 하드코딩 금지
- [ ] 공개 하객 뼈대 `/invitations/p/?t=` (**제안**): 행사 정보만. 하객 명단·RSVP 목록 없음
- [ ] 360px·44px 터치·키보드 포커스·6테마. 전용 CSS는 `src/app/invitations/invitations.css` (**제안**, `activities.css`처럼). `globals.css` 수정 금지
- [ ] 매칭 게이트를 청첩장에 붙이지 않음

확인: 목록에서 만들기→미리보기→공개 링크 복사→하객 화면. 테마 미리보기 「테스트 결제」가 같은 페이지에서 열린다.  
끝난 기준: §3 INV-001 행 + 타입을 다른 사람이 import 가능.  
손대지 않음: RSVP 폼 본문(준혁), 토큰 재발급·보존 패널 본문(한태), 모의 결제 시트 로직(민기 확인).

### 주한태 (INV-002, 목업)

서버 API·RLS·마이그레이션은 이번 없음. **화면에서** 소유자·토큰·보존 안내·하객 비노출을 지킨다.

- [ ] 오하율 타입 PR 머지 후 시작
